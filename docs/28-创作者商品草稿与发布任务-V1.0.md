## 2026-10-15：素材商品验收

V13 预置了四个图片 ZIP 商品，演示店铺可以按既有自有清单归属规则复用这些文件；首次发布接口仍是一个套餐和一个文件。一般新商品没有自动封面映射或分类配置，不能把预置商品的能力说成通用上传功能。详见[素材接入说明](31-已有展示素材接入真实商品.md)。

## 0. 当前实现边界（10 分钟）

| 能力 | 本轮实现 |
| --- | --- |
| 草稿 | 创建新商品的首个 DRAFT 修订；商品 OFF_SALE、发布指针为空 |
| 自有作品 | 查询自己的最新 50 条，包含草稿与已发布作品；刷新后读取数据库 |
| 套餐 | 发布时配置一个套餐，CNY，价格 1～100,000,000 分，名称最多 80 字符 |
| 素材 | 选择自己店铺正式清单中的已有 CLASSPATH 文件；不是任意文件 ID，也没有上传 |
| 发布 | 在事务内创建 Package、Release 1.0.0、单文件冻结 Manifest，再发布修订并使商品可售 |
| 重放 | 同商品、同名称／价格／文件返回原发布结果；不同配置返回 409 |
| 买家 | 新商品进入公开目录，沿原有订单、测试支付、内容库、下载链购买交付 |
| 尚未提供 | 草稿编辑、分类配置、删除、真实上传、审核、新店铺入驻、多套餐／多版本管理 |

当前素材资格从已有店铺的正式清单取得。一个没有正式清单的新店铺没有可复用素材；不能把这一切片描述为所有商家都能自助入驻上传的平台。旧入驻、审核、经营页仍是演示；真实入口是 `/creator/works` 和 `/creator/releases/new`。

停点：能说明“草稿保存”与“准备好可购买交付的商品”分别写哪些表。

## 1. 请求入口与当前用户（15 分钟）

| 动作 | 接口 | 入口 |

[页面](../frontend/src/pages/CreatorProductsPage.vue) → [API](../frontend/src/api/creator.ts) → [发布 Controller](../backend/src/main/java/dev/meteor/product/controller/CreatorProductPublicationController.java) → [Service](../backend/src/main/java/dev/meteor/product/service/ProductPublicationService.java) → [Mapper](../backend/src/main/java/dev/meteor/product/mapper/ProductPublicationMapper.java) → [SQL](../backend/src/main/resources/mapper/ProductPublicationMapper.xml)。

发布请求只包含：

```json
{"packageName":"Basic","priceCents":2300,"fileObjectId":5001}
```

用户 ID 来自 `@AuthenticationPrincipal`，不接受客户端指定用户或店铺。CREATOR 与 CSRF 由 `SecurityConfig` 检查，Service／SQL 仍检查商品和素材归属。匿名 401、买家角色 403、缺 CSRF 403、非法价格 400、不存在／他人草稿 404、不可用素材或发布配置冲突 409。

创建草稿没有幂等保证，重复提交会创建两份；它不等于发布重放。未知网络结果先刷新列表核对，不能盲目重建草稿。

停点：找到 `principal.id()`，解释角色检查为什么不能代替 SQL 中的 owner 条件。

## 2. 发布事务与重放（20 分钟）

按 `ProductPublicationService.publish` 的注释依次阅读：

1. 校验商品 ID、名称、整数分与素材 ID。
2. `findOwnedRevisionForUpdate` 从当前用户的 ACTIVE 店铺找到商品首个修订，并锁行。
3. 已发布时读取原结果：配置相同直接返回；配置不同拒绝。发布后不能通过重放变相编辑。
4. 未发布时要求 DRAFT、OFF_SALE、空发布指针。
5. 查可复用素材、锁住来源，并用真实 Classpath 文件核对大小与 SHA-256。
6. 插入套餐 → Release → Manifest → ManifestItem。
7. 将修订变成 PUBLISHED，再设置商品发布指针和 ON_SALE。

方法上的 `@Transactional` 让整个方法的数据库写入一起提交或回滚。没有任何“上传完成后再补数据”的异步阶段。最后一条状态更新影响行数不是 1，整个事务同样失败。

[ProductPublicationInsert](../backend/src/main/java/dev/meteor/product/mapper/param/ProductPublicationInsert.java) 使用普通 class，因为 MyBatis 要用 setter 回填四个自增 ID，再交给下一次插入。这个对象只在一次事务内部传递，不是新的领域对象或数据表。

停点：画出六次写入；解释如果第四次插入失败，为什么不能留下一个可售空商品。

## 3. 素材资格与冻结清单（15 分钟）

V10 的 `file_objects` 没有 owner 字段。因此不能写成 `SELECT ... WHERE fo.id = 客户端输入` 就允许引用。

当前资格查询沿：

```text
FileObject → ManifestItem → DeliveryManifest → PUBLISHED Release
→ Package → Product → 当前用户的 ACTIVE Shop
```

SQL 同时限制 `storage_provider = 'CLASSPATH'`。API 只返回文件名、媒体类型、大小和 ID，不返回 storageKey。发布前再次执行带 userId 的资格查询并锁行；浏览器的下拉列表不是授权凭证。

发布时新建 Manifest 和条目，复用已验证的 FileObject，不修改源商品的清单。新商品成交时按自己的套餐产生 Grant，再从新 Release 与新 ManifestItem 下载。文件内容复用不等于订单、套餐或权益复用。

停点：在 `reusableFileFrom` 找到 owner 条件，再说明为什么新商品需要自己的 Release／Manifest。

## 5. 面试怎样表达（10 分钟）

可以在理解后说：实现已有店铺的首次商品发布，将套餐、正式版本和冻结交付清单与商品上架放在一个事务中；从 Session 用户校验商品与素材资格，使用商品行锁处理重复／同时发布，并验证新商品购买到下载及交付插入失败回滚。

不能说：实现了任意文件上传、全量商家入驻、审核平台、任意版本编辑或高并发发布。当前只有一个首发套餐、一份已有 Classpath 文件、一个正式版本；对同商品的重放做幂等，不对创建草稿做幂等。
