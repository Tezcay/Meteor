## Day 1：理解项目里的“商品、购买与访问”

状态：2026-09-18 学习者自评理解通过；未逐题提交答案，因此记为概念掌握 `1`，后续在真实设计和实现中再次验证，不继续占用当前学习时间。

### 本课目标

完成后应能不用照文档说明：用户买的是什么；订单、权益和文件为什么不能合成一个布尔字段；一次下载请求经过哪些组件。

### 五个核心对象

| 对象 | 用一句话理解 | 例子 |
| --- | --- | --- |
| Product | 对外展示的稳定商品身份 | “极简求职简历模板” |
| Package | 用户选择购买的内容档位 | Basic、Pro |
| Release | 某个套餐的一次不可变文件发布 | Basic 1.0、Basic 1.1 |
| OrderItem | 购买当时承诺的快照 | 当时套餐、价格、商家和更新策略 |
| EntitlementGrant | 某个订单来源授予的访问资格 | 订单 A 为用户授予 Basic 访问权 |

FileObject 是对象存储里的文件及可信元数据；DeliveryManifest 记录某个 Release 完整包含哪些 FileObject。用户不是因为知道文件地址就能下载，而是因为存在有效 grant，且请求版本和文件满足发布、清单及禁用规则。

### 第一条业务链路

```text
选择 Basic
  → 服务端核价并创建订单快照
  → 测试支付适配器记录支付事实
  → 业务服务验证事件
  → MySQL 事务内把订单置为 PAID，并创建来源 grant
  → 内容库查询有效 grant 和可访问 Release
  → 下载请求再次检查用户、套餐、版本、manifest、文件状态
  → 后端签发短时文件凭证
  → 浏览器持凭证向私有对象存储取文件
```

这里有两个容易混淆的边界：支付系统记录成功，不代表本地订单和 grant 已经成功提交；后端签发了下载凭证，也不代表用户已经完整保存文件。
