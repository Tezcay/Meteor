# Meteor 无障碍审查与修复报告（2026-10-03）

## 1. 结论

本轮不是从“有没有 `alt`”单点判断，而是对公开页、登录、买家工作区和创作者工作区进行代码审查、axe 自动扫描与真实键盘／响应式复核。

修复后结论：

- 11 个核心路由在 axe-core 4.10.2、WCAG 2 A/AA 与 WCAG 2.1 A/AA 规则下均为 **0 条自动违规**。
- 移动端菜单可以用 Escape 关闭并把焦点归还触发按钮。
- SPA 内部路由切换后，焦点会移动到新页面的 `<main tabindex="-1">`。
- 业务表单通过键盘聚焦时有 2px 可见轮廓与 2px 间距。
- 320px 视口检查未出现页面级横向溢出。
- 系统选择减少动画时，首页无限装饰动画实际计算为 `animation-name: none`、`0s`。
- 常见交互目标达到 WCAG 2.2 的 24×24px 最低目标；主要图标按钮和表单动作原则上已提升到 44×44px。

这表示核心页面当前具备较好的无障碍基础，**不表示通过第三方 WCAG 认证**。axe 不能替代读屏、放大、认知可理解性和真实设备测试。

## 3. 审查前确认的问题

### 3.1 对比度不足

首次扫描发现：

- 商品详情预览标签 8 个节点约为 4.08～4.31:1，低于普通文本 4.5:1。
- `/creator/works` 有 1 个节点约为 4.48:1。
- `/creator/releases/new` 有 3 个节点约为 4.49:1。
- `/creator/review` 有 5 个节点约为 4.49:1。

修复方式：加深全局 muted 文本和商品预览非选中标签颜色，并重新扫描真实页面，而不是只在调色板里计算。

### 3.2 全局焦点样式被局部 `outline: none` 覆盖

项目已有全局 `:focus-visible`，但后声明的登录、编辑和后台表单样式使用 `outline: none`，会使部分键盘焦点不可见。

修复方式：为这些输入框、选择框和文本域增加更晚、更具体的 `:focus-visible` 规则。真实键盘复核得到：

```text
activeLabel: 作品名称
outline: rgb(113, 68, 93) solid 2px
outlineOffset: 2px
```

### 3.3 SPA 路由切换不管理焦点

视觉页面已经切换，但浏览器焦点仍可能停留在旧链接上。读屏用户不会自然知道新页面从哪里开始。

修复方式：`App.vue` 监听 `route.path`，等待 Vue 完成 DOM 更新后，把焦点送到 `#page-main` 或 `#main`。实际从“小店订单”点击“我的作品”后结果：

```text
activeTag: MAIN
activeId: page-main
tabindex: -1
heading: 我的作品
```

这里使用 `tabindex="-1"` 是为了允许程序聚焦主区域，不会把 `<main>` 加进普通 Tab 顺序。

### 3.4 移动端菜单缺少 Escape 和焦点恢复

菜单能点击开关，但键盘用户按 Escape 没有反应。

修复方式：在 `InnerHeader.vue` 保存菜单按钮模板引用；Escape 关闭时等待 DOM 更新并恢复按钮焦点。390px 浏览器实测：

```text
打开后 aria-expanded: true
按 Escape 后 aria-expanded: false
activeElement: button.inner-menu-button
activeLabel: 打开导航
```

### 3.5 标题与交互语义不准确

- 发现页同时存在两个可见 H1，页面主主题不明确。
- 作品集合缩略图使用 `tablist/tab`，但交互并不实现完整 ARIA Tabs 键盘模型。

修复方式：发现页保留一个屏幕阅读器可用 H1，其余分区降为 H2；集合缩略图改为按钮组和 `aria-pressed`，与真实行为一致。宁可使用简单、正确的原生按钮语义，也不声明没有完整实现的复杂组件模式。

### 3.6 触摸目标偏小

部分搜索、轮播、评分、集合、预览队列和移动菜单控件为 28～40px。

修复方式：主要图标按钮和业务动作调整为至少 44×44px；链接和其他可交互元素在 320px 首页检查中没有低于 24×24px 的可见目标。

### 3.7 减少动画规则被 CSS 层叠覆盖

代码中原本已有 `prefers-reduced-motion`，但无限旋转的 `.poster-carousel::before` 动画在更靠后的样式中重新声明，导致真实计算样式仍为 `carousel-orbit 16s`。

修复方式：减少动画规则显式以 `animation: none !important` 覆盖后续装饰动画。Playwright 在 `reducedMotion: reduce` 下复测：

```text
matchMedia(...).matches: true
animationName: none
animationDuration: 0s
```

这是本轮最典型的教训：源码中“写了无障碍规则”不等于浏览器最终采用了它，必须检查计算样式和真实交互。

## 5. 怎样复测

### 自动扫描

启动前后端后，在开发环境路由加 `?a11y=1`：

```text
http://localhost:5173/?a11y=1
http://localhost:5173/products/1001?a11y=1
```

页面稳定后会生成：

```html
<script id="meteor-a11y-result" type="application/json">...</script>
```

浏览器自动化可以读取该节点；人工也可在 DevTools Console 执行：

```js
JSON.parse(document.querySelector('#meteor-a11y-result').textContent).violations
```

空数组表示本次 axe 规则没有发现违规。该入口满足以下限制：

- 只在 Vite 开发模式存在。
- 只有 URL 显式包含 `a11y` 时才动态加载 axe。
- 生产构建不应加载或运行审查器。

### 键盘清单

1. 从地址栏开始只用 Tab／Shift+Tab 浏览页面。
2. 检查“跳到主要内容”是否出现且能到主区域。
3. 检查每个焦点是否看得见，不被 sticky header 遮住。
4. Enter／Space 能否触发按钮，方向键行为是否与声明的组件模式一致。
5. 打开搜索对话框和移动菜单，按 Escape 关闭。
6. 关闭后焦点是否回到打开它的按钮。
7. 页面内部跳转后，焦点是否来到新页面主内容。
8. 错误、加载和成功消息是否能被辅助技术感知，且不会重复播报。

### 窄屏和减少动画

- 视口改为 320×800，确认 `document.documentElement.scrollWidth === innerWidth`。
- 视口改为 390×844，完整操作移动菜单和核心业务动作。
- 浏览器模拟 `prefers-reduced-motion: reduce`，检查无限动画实际计算值。

## 8. 面试表达与边界

可以说：

> 我没有只依赖自动扫描。先用 axe 找出对比度问题，再人工检查 SPA 焦点、移动菜单 Escape、表单焦点、触摸目标、320px 溢出和减少动画。过程中发现减少动画规则被后续 CSS 覆盖，最终用浏览器计算样式复测为 none。核心 11 个路由在当前 axe WCAG A/AA 规则下为 0 条违规。

不能说：

- “项目完全符合所有 WCAG 2.2 AA 条款”。
- “已经通过无障碍认证”。
- “所有读屏和真机都测试过”。

有证据、能复测、敢讲边界，比一句“支持无障碍”更有面试价值。
