不重做初始化，不从第一课的 Vue 表单开始。继续 [第二课](20-第二课-商品查询与后端分层-V1.0.md)：

2. 15～20 分钟：回看第 6～7 节，追 `getPublishedProduct` 与三张关联表，解释公开商品的状态条件。

停点记录只写：当前方法、已能解释的规则、下次继续处。第二课通过后，补认证，再学订单。

## 1. 后端主线顺序

每次用 10～20 分钟读一小节；不要求一天读完一课。前端只认请求约定，Vue、样式和组件实现均为选读。

| 顺序 | 阅读 | 产出与过关标准 |
| --- | --- | --- |
| 1 | [第二课：商品查询](20-第二课-商品查询与后端分层-V1.0.md)，第 1、5～9 节 | 画 Controller → Service → Mapper → SQL；解释 JOIN、转义、400／404 |
| 2 | [第一课：认证后端](19-第一课-从登录页面看懂一次全栈请求-V1.0.md)，第 1、5～11 节 | 解释 Session、CSRF、BCrypt、当前用户、角色与资源归属的区别 |
| 3 | [第三课：订单](21-第三课-订单创建与幂等-V1.0.md)，请求约定与第 5～14 节 | 解释核价、快照、唯一约束、重复请求与并发竞争 |
| 4 | [第四课：支付](22-第四课-测试支付与事务内权益发放-V1.0.md)，第 5～16 节 | 解释行锁、事件去重、事务与 Grant；明确 LOCAL_TEST 边界 |

第一课可以跳过前端部分，认证后端需要在第三课前补齐，否则无法解释请求中的当前用户与写请求保护。完成买家链后再读 [商家最小发布](28-创作者商品草稿与发布任务-V1.0.md)，把商品供给起点与购买交付连接起来；不同时展开两条学习线。

## 2. 每节课固定动作

1. 从页面或 HTTP 请求记录 URL、方法、输入、状态码和响应。
2. 定位 Controller、Service、Mapper、表；第一次只读这条链。
3. 在真实代码中理解 Java／SQL 语法，不额外做脱离项目的语法题。
4. 找到一个重复、失败或越权分支，以及对应测试。
5. 关文档口述 1～2 分钟；说不清的地方回到具体方法。

可以不展开写 Vue，但要知道 Cookie 和 CSRF 如何到达后端。先掌握已有业务，不为练习而追加表、算法或零碎功能。

## 3. 项目运行与证据

学习源码使用 `E:\VibeCoding\Meteor`，不要混用其他工作树的状态与测试报告。需要检查环境时在该仓库根目录运行：

```powershell
.\scripts\check-learning-environment.ps1
```

完整投递前验收使用：

```powershell
.\scripts\verify.ps1 -RequireContainers
```

容器引擎未运行会使数据库门禁失败，不能把跳过当成验证成功。2026-10-11 的 108 项、106 通过、2 项容器跳过属于历史增量；2026-10-14 已补草稿与最小发布的真实数据库实跑，最新完整统计以日志为准，详见 [执行日志](08-学习执行日志.md)。

本地买家演示需要后端的演示账号和测试支付开关。现有页面保留作为演示入口；生产部署不能沿用固定密码和测试支付配置。

## 4. 学习后怎样进入简历

学会订单、支付、授权与下载后，从 [简历证据清单](27-简历与面试证据清单-V1.0.md) 选择 2～3 条后端能力。每条都需要亲手演示、定位源码、解释一个失败路径及测试边界。

独立小修改用于证明能维护代码：选择已有规则的必要修正，不为了打卡新增功能。不能把 AI 协助实现的项目说成完全独立开发，不能写真实支付、已上线或没有数据支撑的高并发。
