# 评价取舍与版本记录 V0.3.0

日期：2026-09-16。当前入口：[README](README.md)。状态：设计与学习计划调整，无代码、环境安装或实际测试结果。

## 调整依据

用户已明确主投 Java 后端，希望一个月尽量补齐秋招知识，并指出 Redis、Linux、MySQL 在目标岗位与黑马学习路线中有要求；用户已有虚拟机。上一版偏重项目核心可靠性，未把求职覆盖与产品依赖分别安排，Redis 缺少明确学习任务，Linux 介入过晚。

| 项目 | V0.3.0 决策 | 理由与边界 |
| --- | --- | --- |
| 数据库 | 改为 MySQL／InnoDB；新环境优先核验 8.4 LTS，已有稳定 8.0 环境可继续使用 | 贴合用户当前求职和学习材料；尚无代码，无需维护双库。不是认定 PostgreSQL 技术不足 |
| Redis | 本月必学；完成小实验，争取集成公开商品展示缓存 | 学习 key／TTL、数据类型、缓存策略与失效；订单和权益仍由数据库保证；不为使用 Redis 引入库存秒杀 |
| Linux | 第一周开始，使用用户自己的虚拟机 | 学文件、权限、日志、进程、网络与服务部署；暂未检查虚拟机系统和配置 |
| Docker／Nginx | 本月安排基础部署实践 | Docker 不替代 Linux 学习；Nginx 用于静态资源与反向代理；实际部署以基础完成为前提 |
| HTTP | 基础诊断通过即快进 | 方法／状态码可快速复习；Session、跨域、超时、代理排错随任务深入 |
| MQ | 本月了解，核心链路完成后优先做一个独立实验 | 首选一种，例如 RabbitMQ；学确认、重复与失败恢复，不同时学多套 MQ |
| Spring Cloud／ES／K8s | 了解用途，按目标岗位后续补 | 不增加本月正式项目依赖，不通过拆服务制造复杂度 |
| 月目标 | 核心闭环＋MySQL／Redis／Linux 实践；完整 C1 为冲刺 | 新学习范围占用时间，降低产品完成量承诺，不削减验收标准 |

## 版本边界

V0.2.0 原文件保留为历史。当前总体设计和核心设计升级到 V0.3.0；订单、版本、退款与权益语义沿用，主要变化是技术选型和学习实施。具体表结构仍未设计，MySQL 的隔离级别、锁与活动记录唯一性需实现时验证，不能机械照搬 PostgreSQL 的特性或语法。

Redis 实验的意义是掌握并评估缓存，不预设这个小规模应用必然需要缓存，也不预设缓存一定更快。C1 是正确性门槛；缓存、部署和岗位知识分别记录成果，互不冒充。
