## 1. 先确定当前项目定位（10 分钟）

项目名称可以写为：

```text
Meteor 数字作品交易与受控交付平台（学习项目）
```

技术栈：

```text
Java 21 / Spring Boot / Spring Security / MyBatis / Flyway / MySQL 8
Vue 3 / TypeScript / Vite / JUnit 5 / MockMvc / Testcontainers
```

当前准确范围：

```text
公开商品 → Session 登录 → 服务端核价下单 → 本地测试支付
→ 事务内发放权益 → 内容库 → Release → 冻结 Manifest
→ 五分钟一次性票据 → 二次授权 → 文件完整性校验 → 响应准备审计
```

这是一条本地可运行的交易与交付闭环。它没有接入真实支付商，没有生产对象存储，没有部署或高并发压测。

## 3. 90 秒项目介绍（10 分钟）

下面是结构，不要求背原句：

> Meteor 是一个数字作品交易与受控交付学习项目。已有店铺可以创建草稿，配置单套餐与已有素材，事务内发布正式版本和冻结清单，再让买家购买下载。我重点学习服务端核价与成交快照、用户级幂等和唯一约束、支付行锁与事务内权益发放，以及下载时从当前用户逐层授权、一次性票据和文件完整性。商家发布的同配置重放返回原结果，交付写入失败整体回滚。当前严格门禁 124 项全部通过、0 跳过，含 4 项真实 MySQL；支付仍为 LOCAL_TEST，文件限 Classpath 既有素材，没有真实上传、审核、部署或压测。

脱稿时必须包含五项：业务对象、一个并发问题、一个安全边界、一项测试证据、一项未完成范围。
