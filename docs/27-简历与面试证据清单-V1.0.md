## 1. 先确定当前项目定位（10 分钟）

项目名称可以写为：

```text
Meteor 数字作品交易与受控交付平台（学习项目）
```

技术栈：

```text
Java 21 / Spring Boot / Spring Security / MyBatis / Flyway / MySQL 8
Vue 3 / TypeScript / Vite / JUnit 5 / MockMvc / Testcontainers
```

当前准确范围：

```text
公开商品 → Session 登录 → 服务端核价下单 → 本地测试支付
→ 事务内发放权益 → 内容库 → Release → 冻结 Manifest
→ 五分钟一次性票据 → 二次授权 → 文件完整性校验 → 响应准备审计
```

这是一条本地可运行的交易与交付闭环。它没有接入真实支付商，没有生产对象存储，没有部署或高并发压测。

## 3. 90 秒项目介绍（10 分钟）

下面是结构，不要求背原句：

> Meteor 是一个数字作品交易与受控交付学习项目。我主要围绕买家链路完成了 Session 登录、服务端核价下单、本地支付事件、权益发放、版本清单和一次性下载。下单时前端不传价格，后端读取当前可售套餐并保存订单快照；重复和并发请求由用户级幂等键、唯一约束和冲突恢复处理。支付使用默认关闭的 LOCAL_TEST 适配器，在事务中锁定订单、校验金额币种和事件关联，再更新订单并幂等创建 Grant。下载从当前 Session 用户和 ACTIVE Grant 出发逐层校验 Release、Manifest 和文件条目，使用五分钟一次性 token，数据库只存哈希，消费时再次授权并核对 SHA-256。HTTP 响应、错误 JSON 和完成日志由请求编号关联。当前真实支付、退款、生产对象存储和部署还没有完成；自动化基线是 89 项非容器测试通过，2 项 Testcontainers 因本机 Docker 问题仍未取得实际运行证据。

脱稿时必须包含五项：业务对象、一个并发问题、一个安全边界、一项测试证据、一项未完成范围。

## 5. 写进正式简历前的掌握门槛（15 分钟）

- [ ] 我亲手运行过对应页面和正常流程。
- [ ] 我能在 60 秒内找到前端 API、Controller、Service、Mapper 和表。
- [ ] 我能不看稿解释正常路径、一个失败路径和一个并发／越权风险。
- [ ] 我能指出至少一项自动化测试，并说明它没有证明什么。

- [ ] 我能主动说明未实现范围，不等面试官指出。

六项全部完成，才把该条放进正式简历。少于四项时只把它当作当前学习内容。
