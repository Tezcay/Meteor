# Meteor：评价取舍与版本记录 V0.4.0

日期：2026-09-26  
状态：当前有效版本的取舍说明。

## 本次融合结论

V0.4.0 以 V0.3.0 的可靠交易、版本与权益模型为主干，吸收 V0.3.1／V0.3.2 对“多类别文件交付、展示资源与正式文件分离”的补充，并将后续前端讨论沉淀为明确边界。

| 议题 | V0.4.0 决策 | 原因 |
| --- | --- | --- |
| 作品不是单张图 | 商品支持多预览、多文件、系列与作品项 | 插画、摄影、素材包的真实交付都可能是多件内容 |
| 发现页扩容 | 策展系列 + 可分页完整目录；横向轨只用于少量精选 | 一行横向卡片无法承载持续增长的分类内容 |
| 小类如何产生 | 平台受控词表，创作者选分类／标签；AI 只给建议 | 分类稳定、可治理，不把“看起来相似”当事实 |
| 评分 | 加入已购评分，暂不做开放评论 | 有助于购买决策，又避免评论审核与社区治理膨胀 |
| 角色 | 访客、买家、创作者、管理员有独立数据边界 | 菜单与演示路由不能代替服务端授权 |
| UI 方向 | 首页是编辑式入口，发现页是目录，作品优先 | 避免巨型空白、巨型标题、无穷横向轨和模板化商城感 |
| 深色模式 | 延后到建立语义 token 后做独立适配 | 浅色界面反相会破坏作品展示与层级 |
| AI／Agent | 不进入 C1/C2 交易关键路径 | 先保证可解释、可测试和安全的主链路 |

## 保留的既有决定

- Vue 3 + TypeScript + Vite；Java 21 + Spring Boot 模块化单体；MySQL/InnoDB；公开预览与私有交付资源分离。
- 测试支付适配器、Inbox、幂等、按来源 Grant、不可变 Release、短时下载授权、退款后按来源撤权。
- Redis 只作为公开展示缓存的学习／增强项，不能判定权益；MQ、微服务、ES、K8s 不进入当前主线。

## 被明确排除或延后

真实分账、多币种、跨店购物车、会员营销、DRM、通用转码／在线编辑、流媒体、开放评论与社区、自由店铺装修、自动化 AI 分类／审核、复杂推荐。

## 版本使用规则

- 业务、页面、接口与数据实现以 V0.4.0 配套文档为准。
- V0.3.x 及更早版本只保留为历史和取舍依据；遇到冲突，不从旧文档补回已排除的范围。
- 仅修正文案、链接或无语义歧义时使用 0.4.1；改变角色、交易、授权、版本、评分或目录模型时再开 0.5.0。
- 文档中的“建议、首版、后续”不等同于已实现或已验收。
