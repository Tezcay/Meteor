## 1. 投递版交付什么

```text
已有店铺商家创建草稿 → 配置一个套餐 → 选择自己可复用的已有素材
→ 首次发布商品、版本与冻结清单
→ 买家浏览 → 登录 → 核价、快照与幂等下单
→ 本地测试支付 → 权益 → 内容库 → 一次性授权下载
```

MVP 是最小可用业务版本。这里补齐商品供给的起点，而没有扩成完整商家运营平台。新商品使用真实数据库记录，不把旧种子商品购买或演示按钮当成发布验收。

## 3. 当前发布边界

本轮只做新商品的第一次发布：一个 CNY 付费套餐、一个正式版本、一份单文件冻结清单。素材从自己店铺的已有正式清单取得；FileObject 本身没有 owner 字段，发布时必须从当前用户沿清单检查资格，并核对真实文件。

相同 productId 与相同配置再次发布返回原结果；改配置会拒绝。没有上传、审核、草稿编辑、删除、分类配置、新店铺入驻或多套餐运营。新商品在全部目录与关键词搜索可见；未配置分类，不能声称它已进入某个分类筛选结果。

已有演示账号拥有预置店铺与素材来源；空店铺不能借此随意引用别人的文件。这是有明确限制的最小发布闭环，不能宣传为任意商家的自助上传平台。

## 4. 当前学习顺序

你正在第二课，继续第 8 节异常、第 9 节测试：按方法名定位商品 400／404，再说明 Service Stub 与 HTTP 测试的边界。

随后补第一课认证后端，再依次学习订单、支付、授权、下载与集成测试。最后读发布专题；不要因为新功能完成就同时打开全部文件。[主路线](17-零基础项目学习路线-V1.0.md) 保留短主线。

## 5. 后续不再默认扩张

- 不自动加表、消息队列、缓存、退款、评价或经营小功能；已执行迁移不修改。
- 不把保存草稿、选择本地文件名、设计预览或本地评分当成真实发布、上传或评价。
- 今后变更共用权限、异常、DTO 或状态，同轮检查受影响的前置课。
- 投递前的主要剩余工作是学习掌握与材料表达；在线部署／视频按实际投递需要再决定。
